# SuspensionGeometryLab 懸吊幾何工作台

## GitHub Pages 網頁版

[開啟 SuspensionGeometryLab](https://dannyhsuc10.github.io/Suspension-geometry/)。
英文網頁版包含 Front FV、Rear FV、Side View、Wheel End 3D 與 Static Full Car，支援全車設定、24 點硬點模式、專案 JSON、LapSim CSV、資料與圖表匯出，以及 FV／SV／靜態全車的 STEP 匯出。Pacejka 輪胎模型僅在桌面版提供。網頁使用同一套幾何求解器，匯入的專案與圈速資料會在瀏覽器內處理。

要在本機預覽網頁版，在儲存庫根目錄執行以下指令，然後開啟 `http://localhost:8000/`。瀏覽器首次啟動會下載 Pyodide 與 NumPy。

```powershell
python docs/build.py build/web
python -m http.server 8000 --directory build/web
```

## 桌面版

本工具是獨立的六頁 Tkinter 桌面介面。Canvas 圖表、平移縮放、捲動元件與 CSV 匯出均包含在本資料夾內，可單獨複製整個 `SuspensionGeometryLab` 資料夾使用。完整靜態構造直接呼叫套件內的 `static/fv/wireframe_geometry.py`，與套件內的 `static/fv/tk_wireframe.py` 使用相同來源。FV、SV 的運動零位均來自這份靜態結果；WE3D 與輪胎模型使用其中合併 FV / SV 的真實 3D 主銷。

幾何程式已收進 `suspension_geometry_lab/static/`，輪端旋轉函式位於 `suspension_geometry_lab/wheel_end_geometry.py`；全部使用套件內 import，不依賴 `VehicleLab`、`vehicle_lab` 或 `new` 資料夾。圖表基底位於 `suspension_geometry_lab/chart_base.py`，捲動元件位於 `suspension_geometry_lab/widgets.py`。

## 啟動與參數操作

在本資料夾雙擊 `Start-SuspensionGeometryLab.bat`，或先切換到 `SuspensionGeometryLab` 資料夾再執行：

```powershell
python -m suspension_geometry_lab
python -m suspension_geometry_lab --project projects/my_suspension.json
```

也可執行 `python run.py`。專案 JSON 可儲存在本工具自己的 `projects/`。

獨立靜態線框預覽可雙擊 `Start-StaticWireframe.bat`，或執行 `python -m suspension_geometry_lab.static.fv.tk_wireframe`；同樣使用套件內幾何程式。

需要 Python 3.10+、Tkinter 與 NumPy；PNG 匯出需要 Pillow。這台電腦的 Codex Python 已具備套件。其他環境可安裝：

```powershell
python -m pip install -r requirements-suspension.txt
```

1. 按右上「共用車輛／懸吊設定」，可編輯車輛 / 輪胎、24 個硬點、前後軸參數與掃描範圍，並選擇懸吊參數模式或硬點模式，再按「套用全部設定」。
2. 參數模式下，各幾何分析頁左側也可編輯相關設計；硬點模式下，懸吊欄位顯示唯讀反算值，共用車輛與掃描設定仍可編輯。按「套用左側參數並重新解算」後，各頁會使用新幾何，舊幾何結果與掃描快取會清除。未套用的輸入框內容尚不屬於專案。
3. 按「儲存專案」或 Ctrl+S 儲存 JSON。按「另存專案」可保留不同設計版本，按「匯入」或 Ctrl+O 可載入專案。檔名旁的 `*` 表示已套用設定尚未儲存。
4. 選擇圖表，拖動滑桿觀察目前姿態。拖曳過程會持續求解、顯示已完成的姿態，再接續求解最新滑桿位置，不必放開滑鼠。曲面與範圍圖是整個設定範圍的掃描，不會隨目前姿態改變掃描邊界。
5. 3D 圖拖曳旋轉，2D 圖拖曳平移；滾輪縮放。幾何圖與 RC / PC 位置分布圖的 X、Y 軸維持相同單位的等比例，視窗縮放後也會維持。滑桿更新時保留目前縮放、平移與視角；按「重設視角」或雙擊才會重新置中。切換圖表、座標模式、車軸或套用新設計時會重新配合圖形範圍。結果表可捲動查看所有數值。

未指定 `--project` 啟動時，基準專案為 `suspension_geometry_lab/default_project.json`；指定時則載入該專案。預設前後驅動力比例為 **50%：50%**（`drive_force_front=0.5`，後軸自動為 `1−0.5`）。其餘基準幾何沿用 `static/car.py` 的原始設定，包括前後 FVSA 1 m、RC 35 / 40 mm、KPI 12 / 13 deg、caster 5 / 0 deg。工具的可編輯設計值只讀 JSON；套件內的 Car / Suspension 類別只用作靜態求解器的型別介面，不會呼叫它們的預設值建構子。獨立靜態線框預覽仍可使用原有設定。

本工具與原 Vehicle Lab 的 JSON 結構不同；兩者用途、硬點來源與參數種類不同，開啟錯誤格式會明確顯示錯誤。

以「匯入」或 `--project` 開啟專案 JSON 時，完整檔案會直接開啟。若有缺失，程式會依檔案的 `schema_version` 在「補齊專案缺失欄位」視窗列出缺少的欄位、`null` 或空白值。可逐格輸入，或留空採用該格的預設值，再按視窗右上角的「補齊並匯入」。A 臂 X 的 `null` 代表自動採用幾何極限。硬點的建議值優先使用同名對側座標鏡射，兩側都缺時採用基準車輛的座標。補齊後須通過專案與幾何驗證，儲存時會提示選擇新檔位置。

## 輸入上下界與關聯檢查

共用設定與各幾何頁左側的一般設計參數、掃描設定輸入框下方顯示允許範圍；硬點 XYZ 與 A 臂車身 X 不設人工數值上下界。輸入途中可暫時留白或輸入負號，無效數值會以橘色標示；按套用時必須修正，無效草稿不會覆蓋已套用的設計。讀取與儲存 JSON 也使用相同的數值驗證，不會自動截斷輸入值。專案名稱允許 1～128 字元，不可全為空白。

以下為本工作台的設計輸入保護範圍，並非賽例規範或可製造性認證；各欄單獨合格後，仍須通過關聯與幾何求解檢查。除特別註明外，包含上下界。

| 車輛／輪胎欄位 | 允許範圍 |
|---|---|
| 軸距 | 0.5～5 m |
| 重心至前軸 | 大於 0、至多 5 m，且小於軸距 |
| 前／後輪距 | 各 0.4～3 m |
| 重心高度 | 0.05～1.5 m |
| 總質量 | 50～2000 kg |
| 重力加速度 | 9～10 m/s² |
| 車底離地高 | 0～0.5 m，且不高於重心 |
| 輪胎自由半徑 | 0.1～0.6 m |
| 輪胎垂直剛性 | 10000～1000000 N/m |
| 胎寬 | 0.05～0.6 m |
| 輪圈內徑 | 0.1～1 m，且小於輪胎自由直徑 |
| 輪圈避讓間隙 | 0～0.1 m，且兩倍間隙小於輪圈內徑 |
| 靜態避讓轉角 | 0～80 deg |
| 前煞車比例 | 0～1，後軸為 1−前軸比例 |
| 前軸加速驅動力比例 | 0～1；後軸自動為 1−前軸比例 |
| 前後總側傾剛性比 KφF／KφR | 大於 0 的有限數值；預設 1，含彈簧與防傾桿，前後使用同單位 |

| 前／後軸欄位 | 允許範圍 |
|---|---|
| FVSA | 0.05～20 m |
| Roll center 高度 | −0.5～1 m |
| KPI、Caster | 各 −45～45 deg |
| 靜態 Camber | 各 −20～20 deg；負值輪頂向內傾，左右鏡射 |
| Scrub radius、Mechanical trail | 各 −0.3～0.3 m |
| Au／Al 輪心上／下偏距 | 各 0.005～0.5 m |
| 上／下 A 臂車身 \|Y\| | 各 0～1.5 m，且小於該軸半輪距 |
| 前／後軸 Anti 比例 | 接受有限數值，並檢查是否可解出有效幾何 |
| 前／後軸有號 SVSA | 有限值，且絕對值至少 10⁻⁸ m |

參數模式的每一軸都輸入 Anti 比例與 SVSA。硬點模式顯示由實際幾何反算的兩個值。

| 掃描欄位 | 允許範圍 |
|---|---|
| 上壓／下垂行程 | 各 0～200 mm，不可同時為 0 |
| 轉向範圍 ± | 大於 0、至多 80 deg |
| Caster 掃描下／上限 | 各 −45～45 deg，且下限小於上限 |
| 每軸網格點數 | 5～51 的整數 |

另檢查前後軸的輪胎負載半徑均大於 0。求解器會拒絕接點重合、A 臂共線或上下球接點順序錯誤等無效幾何。掃描範圍內的不可達姿態會標為無解。

硬點 XYZ 不設固定或依車輛尺寸推算的人工數值上下界，也不限制 Z 必須非負。仍須輸入三個有限座標，保留左右側別、鏡射對稱與既有 A 臂幾何檢查。預設使用參數模式，24 個硬點由幾何產生實際座標；直接編輯 XYZ 時仍使用實際數值，不將 XYZ 設為 `null`。

A 臂車身 X 不設固定數值上下界；八格預設皆為空白／`null`，自動採用輪圈避讓幾何算出的極限接點。手動指定 X 時仍須符合該支 A 臂的實際幾何條件，見下一節。

新編輯的設計欄位在套用時取到最接近的級距，正好在兩格中間時取離零較遠的一格。

| 設計欄位 | 級距 |
|---|---|
| 前／後輪距、FVSA、上下 A 臂車身 \|Y\| | 0.005 m |
| RC 高度 | 0.001 m |
| KPI | 0.5° |
| Caster | 0.1° |
| 靜態 Camber | 0.1° |
| Scrub radius、Mechanical trail | 0.001 m |
| 所有 Anti 目標 | 5 個百分點（JSON 比例 0.05） |

未編輯的設計值保留完整精度。姿態表、CSV 與報告列出軸端及加權 Anti，曲面使用加權值。5 個百分點的級距只用於編輯設計目標。

### 前視靜態 Camber 輸入與校正

「前 FV」與「後 FV」頁在 RC 高度下方各有獨立的「靜態 Camber（負值向內傾）」數值輸入框，單位度、預設 0°、級距 0.1°。前後軸獨立，同軸左右輪使用相同的內／外傾值並鏡射；例如前軸輸入 −2°，零行程的 FL、FR 均為輪頂向內傾 −2°。按「套用左側參數並重新解算」生效。共用設定、靜態全車與 WE 頁亦同步此值。硬點模式仍可編輯這個車輪安裝角，不改動 24 點 XYZ。

建構順序固定：先以 **Camber＝0** 求解 A 臂、球接點、主銷、輪心、輪圈避讓與車身接點，再以既有輪心為中心，對車輪／輪圈施加縱向旋轉。A 臂、球接點、主銷與輪心均保留原構造，靜態 3D、FV 動態輪胎及 WE 轉向模型則使用調整後的車輪姿態。輪圈避讓線仍是原先 0° 的構造參考，非零 Camber 時列為參考線。

傾斜後，負載半徑中心圓的最低點會相對輪心產生橫向與垂直偏移。FV 使用此校正接地點建立接地座標、RC 力線與 Camber；RC0 也改用同一安裝角的零行程結果，因此實際零位 RC 可與原 0° 構造的 RC 設計輸入有小幅差異。原始 0° 接地參考點另存為 `L_travel_reference`／`R_travel_reference`，行程控制仍沿用這份機構基準；CSV 輪心相對行程的解算也保留原定義。RC 搜尋會使用校正後的接地位置。

Camber 分布的「初始Camber＋車身姿態」先套用初始角，再加上 CSV 的 roll／pitch；「姿態＋懸吊」另包含 A 臂運動，「姿態＋懸吊＋轉向」再繞當前主銷轉動。各階段均以車輪方向向量相對道路計算角度，包含 pitch 與轉向時不以單純數值平移取代旋轉。FVSA 搜尋的全圈最大 |Camber| 採相同校正；Pacejka 的 Camber 留白時也使用校正後幾何，手動指定則仍代表該輪的總 Camber。

專案前、後軸各新增可選的 `static_camber_deg`，缺省的舊專案以 0° 載入，不需補填；儲存會保留此值，格式仍為版本 7。輸入快照與 FV CSV 包含靜態角度，參數模式的靜態硬點 CSV 在非零角時額外記錄實際與構造接地點。

輪心與車身保留構造基準，未重新求解車高／pitch 平衡使四輪落在同一水平面；接地點沿用負載半徑中心圓近似，未加入胎肩、有限胎寬或彈性接觸求解。SV 仍採原本的零 Camber 側視機構近似。

### 尋找最佳 FVSA

「前 FV」與「後 FV」頁左側 FVSA 旁有「尋找最佳FVSA」按鈕。每次點選均先要求選擇賽道 LapSim CSV，再輸入最大允許 **|Camber|（度）**。以該頁目前左側草稿的該軸輪距一半作為精確起點，每次增加 FVSA 最小設定級距 **0.005 m**；若半輪距為 0.6275 m，則依序試算 0.6275、0.6325、0.6375 m。其餘設計與 RC 高度維持草稿值。

每個候選值重新建立幾何，使用 CSV 四輪相對位移的對應輪心行程，以及 `roll_deg`、`pitch_deg`，重算左右輪相對道路的外傾角。判定取**全圈所有資料的雙輪最大絕對值**，包含直線、左彎與右彎；不採用 CSV 中已算好的 camber 欄位，也不省略無法求解或超出工作行程的資料。與既有圈速 Camber 圖的 FV「姿態＋懸吊」定義相同，未包含轉向效應。CSV 須包含四個 `zs_minus_zu_*_mm`、`heave_mm`、`roll_deg`、`pitch_deg`，以及 `curvature_1_m` 或 `ay_g`。

最大 |Camber| 等於容許值時仍合格。首次超過時停止，選擇前一個合格的最長 FVSA，自動套用左側參數並重新解算；不再往更長的區域繼續搜尋。若起點即不合格則保留原設計。遇到無效幾何、手動 A 臂 X 超出候選幾何範圍或賽道姿態無解時，同樣停止並回報原因；若已有合格候選值，採用停止前最後一個合格值。搜尋至允許上限 20 m 仍未超限時，回報範圍內最長值。結果列出最大 |Camber|、其有號數值、輪位、資料筆次與下一級超限數值。

搜尋在背景執行，可取消；取消或結果過期時不套用設計。硬點模式按鈕停用。此功能固定匯入 CSV 的行程與車身姿態，不會重跑圈速／車身動力學；結果僅適用於該份資料與目前幾何設定。改變 FVSA 後，若要重新確認 RC 的全工作範圍條件，可再執行「尋找最佳roll center」。

### 尋找最佳 SVSA

「SV 側視」左側前、後軸的 SVSA 欄位旁都有「尋找最佳SVSA」按鈕；兩個按鈕均開啟同一個前後軸最佳化視窗，一次輸入三項設定：

| 設定 | 預設 | 判定 |
|---|---|---|
| 目標 Heave | 7 mm | 相對零行程的前後輪同量上壓，Pitch＝0；可輸入目前行程範圍內的負值表示下垂 |
| 前輪 Caster 絕對變化量下限 | 0.15 deg | `|Caster(Heave) − Caster(0)| ≥ 下限` |
| 後輪 Caster 絕對變化量上限 | 0.1 deg | `|Caster(Heave) − Caster(0)| ≤ 上限` |

前輪從 **1 m** 開始，每次 **+0.5 m**，最多到 **15 m**。首次 Caster 變化量不足或幾何／目標姿態無解時停止，選上一個合格長度；若 1 m 即失敗，則沒有前輪結果。若到 15 m 都達標，選搜尋範圍內的最長值 15 m。這是依首次失敗停止的規則，不會跨過失敗點繼續尋找其他區間。

後輪從最短有效長度 **0.5 m** 起，每次 **+0.5 m**，最多到 **15 m**，選第一個不超過上限且幾何有效的長度。較短長度若幾何／目標姿態無解，會略過並繼續檢查。0 m 是退化的 SVSA，無法建立有效瞬心，因此不作為候選；此 0.5 m 間隔只用於最佳化，不改變原本手動輸入 SVSA 的規則。

搜尋沿用目前左側草稿的 Anti、初始 Caster、其他幾何與行程範圍，只改兩軸 SVSA；Caster 變化量使用未取整的計算值，保留 0.15° 等細小門檻，不受設計 Caster 0.1° 輸入級距影響。前後分別搜尋後，會再用兩個選定長度共同解算零行程與目標 Heave，確認兩項條件同時通過才一起套用。若任一軸找不到解、組合無解、取消或專案在設定／搜尋期間變更，均不套用部分結果；硬點模式的按鈕停用。

套用後更新前後 SVSA 欄位，並將 SV 圖與下方姿態表移到指定 Heave，顯示零位／目標 Caster、有號及絕對變化量、前軸停止原因與後軸檢查筆數。設定值在本次開啟工具期間保留。使用基準專案與預設 7 mm／0.15°／0.1°，結果為前 SVSA **2.5 m**（變化約 0.160422°）、後 SVSA **4.5 m**（約 0.089124°）；前 3 m 約 0.133690° 未達下限，後 4 m 約 0.100263° 超過上限。

此功能使用既有 SV 平面固定切線模型，**只比較零行程與指定 Heave 兩個姿態**，不搜尋整個工作行程的最大 Caster 變化，也不重新模擬圈速或要求匯入 CSV。

### 尋找最佳前輪 Caster

在「SV 側視」或「WE3D 輪端」左側的**前軸 Caster** 旁按「尋找最佳Caster」。搜尋範圍固定為 **3～6 deg**，使用 Caster 最小設定級距 **0.1 deg**，包含兩端共 31 個候選角度；評估全部角度後，選擇外側前輪「姿態＋懸吊＋轉向」Camber 常態分布峰值最接近 0° 的候選。其餘參數沿用該頁左側草稿，只調整前輪 Caster；誤差相同時取較小角度。

優先使用目前已匯入的賽道 CSV；尚未載入或缺少姿態／轉角資料時，會要求選擇 CSV。檔案需要四輪相對位移欄位、`heave_mm`、`roll_deg`、`pitch_deg`、`curvature_1_m` 或 `ay_g`，以及每筆的左右前輪轉角 `steer_FL_deg`、`steer_FR_deg`。使用既有圈速 Camber 計算：正的轉彎訊號視為左轉，外側為 FR；負值為右轉，外側為 FL。合併左右轉的外側輪，排除直線，包含已設定的靜態 Camber；每筆有效彎道資料等權，不採用 CSV 既有的 Camber 結果欄位。

目標使用輪端分布圖相同的原始角度、常態擬合及有效樣本規則：

```text
資料欄位：outer_camber_steered_deg
常態曲線峰值位置 = 平均值 μ
最佳化目標 = 最小化 |μ|
```

不是選直方圖最高格的中心，也不是最小化最大絕對 Camber 或標準差。結果列出搜尋前後峰值、標準差 σ、實際 Camber 範圍、有效彎道數與排除直線數；若最接近 0° 的結果位於 3° 或 6° 界線，會註明只代表該範圍內的最佳值。至少需要兩筆有效樣本且標準差大於 0，才能建立常態曲線。

無法到達的彎道姿態沿用目前圖表的排除規則，所有候選必須使用同一組有效樣本，避免靠少算部分資料改善峰值。候選幾何或手動 A 臂 X 無效時會排除該角度，繼續評估其餘角度。找到結果後自動套用前輪 Caster、切到 WE3D 的「LapSim 過彎 Camber 分布」，並開啟外側「姿態＋懸吊＋轉向」的常態曲線，方便核對峰值；專案標為未儲存。取消、沒有有效常態曲線、專案或 CSV 在搜尋期間變更時不套用；硬點模式的按鈕停用。

搜尋固定 CSV 的車身姿態、行程及轉角，不會重新模擬圈速或整車動態；峰值接近 0° 不代表全部樣本或最大 Camber 都接近 0°。

### 尋找最佳 Roll center

「前 FV」與「後 FV」頁左側的 Roll center 高度旁有「尋找最佳roll center」小按鈕。前軸輸入 **RC 設計高度搜尋起點**，單位 m，預設 `-0.005`，再以 **0.001 m** 級距往上搜尋最低合格值，至允許上限 1 m；起點未對齊級距時採範圍內第一個較高的候選值。後軸則依下述公式**直接解析求解**，輸入框改為允許的 RC 設計高度最低界線（同樣預設 `-0.005 m`），上限 1 m，不再逐一掃描高度。

搜尋採用該頁目前的左側參數草稿及上壓／下垂行程，對左右輪各以不超過 1 mm 的間隔取樣，包含上下界與零行程，再檢查完整左右行程組合，涵蓋 heave 與 roll。RC 高度使用目前兩接地點連線的向上法線座標 y′，所有取樣姿態均須嚴格高於地面；觸地、地下、不可達姿態、無有限瞬心或 RC 均不合格。亦檢查 A 臂及 RC 力線的平行行列式與其符號變化，排除取樣間可見的無窮遠跳變；手動 A 臂 X 若超出候選幾何極限，也不接受退回解。

前軸的第一個合格值就是該搜尋起點、設定級距與取樣條件下的最低值。找到後自動套用左側參數與最佳 RC 高度、重新解算，並列出行程內最低 RC、其左右行程、最大橫向 |x′| 及檢查筆數；專案會標示未儲存。取消、無解或搜尋期間專案已變更時不套用結果。硬點模式下 RC 是反算結果，此按鈕停用。

這是現有 FV 平面近似的有限取樣搜尋，不能保證取樣間的連續機構沒有更窄的穿地或奇異區間，也未約束最大橫向位移；結果只適用於當次指定的設計與行程範圍。

#### 後軸 RC：解析求解前後載荷轉移量相等

後 FV 的共用欄位新增 **前後總側傾剛性比 KφF／KφR**，並提供前後輪距、軸距、重心至前軸距離、重心高度。剛性比使用換算至輪端的前後軸總側傾剛性，包含彈簧與防傾桿；不是彈簧本體剛性比，也不是輪胎垂直剛性比。預設 1 表示前後相同，舊專案缺少此欄時也採 1，且不改寫原檔；實際值請依車輛設定輸入。

前後靜態重量比由 `wF = 1 − cg_to_front / wheelbase`、`wR = 1 − wF` 計算，並在後 FV 左側即時顯示。調整軸距及重心位置會同步改變重量比，避免另外輸入一組與幾何矛盾的軸重分配。

依 [how_to_find_rear_roll_center.md](how_to_find_rear_roll_center.md) 固定目前已套用的前軸 RC 與前軸機構，直接求出後軸 RC 高度。目標已改為**零行程前後載荷轉移量相等**，亦即前後各占 50%；重量比仍用於側向力分配，目標不再是讓載荷轉移占比等於重量占比。將共同的 `m·ay` 約去後，文件中的解析式可寫為：

```text
r = KφF / KφR；λK = 1 / (1+r)
A = wF / track_front
B = wR / track_rear
C = (1−λK) / track_front − λK / track_rear
hRCR = [A·hRCF + C·(hCG − wF·hRCF)] / (B + C·wR)
目標：ΔFzF = ΔFzR，亦即前軸載荷轉移占比 = 50%
```

`ΔFz_i` 是由內輪轉移到外輪的負載量。總質量與共同側向加速度在等式中相消，因此只需剛性比，毋須另外輸入剛性總值或側向 G。程式以等價的正值形式 `B+C·wR = wR·(1−λK)·(1/track_front+1/track_rear)` 計算分母，避免兩大數相減造成精度損失；無有限解時顯示原因。

`hRCF`／`hRCR` 使用實際零行程接地座標高度，包含靜態 Camber 的接地修正；重心高度亦按前後靜態接地面在重心處插值修正。機構仍先以 Camber＝0 建立，程式解析反算車輪安裝角造成的接地變化，將物理 RC 解換回草圖的 `rc_height` 設計高度，全程無數值迭代或高度掃描。剛性輸入已是側傾剛性，公式不再乘一次輪距平方。

解析設計高度按最小設定級距 **0.001 m 四捨五入**後，只驗證這一個設計的完整前後軸工作行程；取樣方式與前軸搜尋相同。若原始解析設計高度或取整值超出允許界線、幾何無解、手動 A 臂 X 超限，或前／後軸任一全行程檢查失敗，顯示解析解與原因，**不套用、不截斷到邊界，也不另找其他高度**。合格時才自動套用，並顯示物理 RC 解析值、換算的設計高度、取整值、求解前後載荷轉移占比及取整後的殘餘誤差（相對 50% 的百分點）。取消或結果過期時同樣不套用。

此方法將總質量視作簧上質量，假設剛性車身，忽略空力、簧下質量力矩、輪胎負載敏感性、柔順轉向及動態側傾平衡；**只求零行程的前後載荷轉移量相等，不代表全行程或全圈的轉向不足梯度相同，也不保證中性轉向**。實際轉向不足梯度仍需輪胎側向力／側偏剛性隨負載變化的模型與指定工況。背景可參考 [OptimumG 的側傾與載荷轉移說明](https://optimumg.com/rolling-about/)及[轉向不足係數研究中的輪胎與懸吊因素](https://www.mdpi.com/2076-3417/9/24/5428)。

## A 臂車身接點的八個 X 設定

共用設定的「前軸參數模式」與「後軸參數模式」頁籤各新增四個欄位：上 A 臂前／後接點 X、下 A 臂前／後接點 X，共八個參數。輸入單位為 **mm**；使用全車座標，X 向前、前軸 X=0、後軸 X=−軸距，並非相對各輪心的距離。每組數值同時用於左右兩側。

欄位留白時使用原本輪圈避讓幾何求出的極限接點，保留舊專案的行為。原來標為「FV 上／下接點 X」的欄位，現改標為「上／下 A 臂車身 |Y|」，仍以 m 輸入，避免與新增的全車縱向 X 混淆。

接點計算先保留 A 臂參考平面與指定的車身 Y，將輸入 X 代入平面方程解 Z。若平面法向量為 n、平面上一點為 P₀：

```text
Z = P₀z − [nx·(X−P₀x) + ny·(Y−P₀y)] / nz
```

每次計算都重新以輪圈避讓幾何取得該支 A 臂的最前、最後接點，作為 X 的閉區間範圍。前後兩個 X 都必須在範圍內，且 `後接點 X < 前接點 X`；不可重合或前後顛倒。範圍內的邊界值允許使用。

同一支 A 臂只要任一接點超限、順序錯誤，或固定 X、Y 後無法唯一求 Z，**草稿預覽的兩個車身接點皆回到原本的極限解**；其他 A 臂仍使用各自有效的設定。輸入值保留，不會靜默改寫：欄位旁顯示目前允許範圍、實際採用的 X，超限處標註「超過極限範圍 xxx mm」；順序錯誤則顯示具體原因。桌面介面會拒絕套用或開啟含此類違規 X 的參數模式專案，必須修正輸入或留白，才可更新正式設計。

例如目前基準的右前上臂 X 極限約為 −274.529504～288.500086 mm。設定前 X=200、後 X=−200 mm 時，兩點的 Y 沿用 −255 mm，Z 由 A 臂平面求解；若前 X=400 mm，標註超出約 111.5 mm，前後兩點都使用原本極限解。

這八個欄位輸入後會自動更新範圍與超限標註；尚未編輯過硬點草稿時，也會同步更新表中的產生座標。按「由目前參數重新產生 24 點」可將目前有效設定或極限退回結果寫入硬點草稿，再切換至硬點模式。勾選直接編輯 XYZ 時，八個參數欄位停用，仍保留原本設定；此模式的 24 個原始 XYZ 不會被這八個參數覆蓋。

JSON 使用可選的 `arm_mount_x` 欄位，包含前後軸各四個 X，內部單位 m，`null` 表示自動使用極限；目前 `default_project.json` 明確將這八格全部設為 `null`。不含此欄位的舊專案同樣採用自動極限。核心腳本仍可讀寫舊的退回設定供檢查，桌面介面則執行上述套用檢查。HTML 報告另保存 `mount_position_checks`，記錄要求值、實際值、當時極限、超出距離與退回原因。

## 參數模式與 24 個懸吊硬點

預設維持懸吊參數模式。第一次開啟共用設定時，硬點表由目前參數解出的靜態場景產生；可按「由目前參數重新產生 24 點」更新草稿。若尚未手動編輯硬點，在同一視窗修改參數後勾選硬點模式，也會先使用最新參數產生座標。此按鈕會取代目前的硬點草稿，但不會在按「套用全部設定」前改動專案。

勾選「使用直接修改硬點 XYZ」後，在「24 個懸吊硬點」頁籤雙擊點名，輸入以逗號分隔的 X、Y、Z。表格與輸入框為 **mm**，JSON 與硬點 CSV 為 **m**。每輪六點，四輪共 24 點：

| 點名 | 定義 |
|---|---|
| UCA_F / UCA_R | 上 A 臂前／後車身接點 |
| UBJ | 上 A 臂外側球接點 |
| LCA_F / LCA_R | 下 A 臂前／後車身接點 |
| LBJ | 下 A 臂外側球接點 |

座標沿用 Vehicle Lab：X 向前、Y 向左、Z 向上；前軸 X=0、後軸 X=−軸距，地面 Z=0。修改 FL / FR 或 RL / RR 的任一點，對側同名點立即更新為 `(X, −Y, Z)`，不改動其他點。左右必須保持鏡射對稱；JSON 中的非對稱座標會明確拒絕。以 Y 值反號實作左右鏡射也可見 [MathWorks 的雙 A 臂硬點定義](https://www.mathworks.com/matlabcentral/mlc-downloads/downloads/33547d1c-88ab-48d1-9559-d39bc1c7a2db/1739468692/previews/Libraries/sm_car_doc/suspensions/html/sm_car_doc_susp_double_wishbone.html)。

右側顯示硬點反算的 KPI、caster、scrub radius、mechanical trail、FVSA、RC、SVSA、anti 與等效車身樞點等唯讀結果。硬點模式下，各分析頁的懸吊欄位同樣顯示反算值，不能直接編輯；共用車輛與掃描設定仍可編輯。原本的參數模式設計值保留，取消硬點模式後會恢復以該組參數求解；已編輯的硬點也會保存在專案中。未套用或取消視窗不會改變目前專案，無效幾何不會覆蓋已套用結果。

反算預覽自動更新：編輯硬點後立即重算；修改車輛／輪胎等欄位後，停止輸入約 0.2 秒便會刷新結果，無須手動按更新。這只更新草稿預覽，仍須按「套用全部設定」才更新正式分析。

硬點能反算靜態幾何，但目前的少量設計參數無法唯一重建全部 XYZ。尤其四個車身接點的縱向位置、旋轉軸傾角，不能只靠 FVSA、RC、KPI 等數值完整保留。因此硬點模式**以原始 24 點為幾何來源**，反算參數是結果，不會再用反算值重建並覆蓋座標。現有基準參數輸入的前 RC 為 35 mm；從產生的實際 3D A 臂旋轉軸反算，約為 34.76035 mm，兩者的差異會如實顯示。

硬點模式的分析方式：

- 靜態全車直接畫出原始 24 點及上下 A 臂；硬點 CSV 輸出相同的 24 個點名與座標。
- FV 在上、下球接點各自的 X 平面與對應 A 臂旋轉軸求交，作為等效 2D 樞點；以此反算零位 RC、FVSA 並沿用現有四連桿運動。這保留零位投影的瞬時運動方向，有限行程仍屬平面近似。
- SV 由每支 A 臂繞實際車身接點軸線的零位速度，取得 XZ 投影切線與側視瞬心，沿用固定切線與剛性羊角的運動近似。瞬心或中心位於無窮遠、沒有有限交點時，相關值顯示 N/A，不沿用舊數值。
- WE3D 使用輸入 UBJ–LBJ 定義的實際主銷軸，以原始輪心做 Rodrigues 轉向旋轉；caster 曲面與曲線使用這份硬點的設計 caster。

輪心仍由車輛軸距、輪距與負載輪胎半徑定位；六點不含輪心／輪胎姿態設定或轉向拉桿，未增加 bump steer 或行程與轉向耦合的完整空間求解。前後車身接點必須分離、A 臂三點不可共線、UBJ 必須高於 LBJ；目前 FV 等效樞點模型要求兩個車身接點有非零 X 間距。無法分析的草稿會顯示具體原因。

專案 JSON 支援可選的 `hardpoints: {enabled, corners}`，目前儲存格式為 `schema_version=7`，原有版本 1～6 專案可直接開啟。HTML 報告的 `static_parameters` 記錄軸端 Anti、SVSA 與加權 Anti，水平正向均朝另一軸。

### Pacejka 回正力矩

進入「輪胎模型 · Pacejka」後，預設為「前軸 FL + FR」。左、右輪各有一欄工況，輸入後按「計算輪胎力與力矩」。分析輪位也可切換為 FL、FR、RL 或 RR。輪胎參數預設為 `Hoosier_43075_R20_W8_direct_candidate.tir`，可切換內建配方或用「匯入 .tir」載入自己的 MF6.1 SI 參數。前軸的兩輪共用同一份 TIR。輪荷留白時採專案的靜態單輪荷重。胎壓與前進速度留白時採 TIR 的 `NOMPRES` 與 `LONGVL`。主銷轉向沿用 WE3D 的靜態懸吊高度和轉向幾何。

「Camber 外傾角 (°)」可直接指定各輪外傾角。四輪皆以輪頂向車身內側為負、向外側為正，輸入 `0` 表示直立，留白採轉向後的幾何外傾角。「車輪姿態」會隨主銷轉向角、側偏角和 Camber 即時更新。切到「後視」可用鉛直基準核對輪頂內傾或外傾，切到「俯視」可比較車輪朝向和行進方向。

模型以輪胎側偏角和縱向滑移率計算混合滑移的 `Fx`、`Fy`、`Mz`。沿輪胎朝前為 +X，向左為 +Y，路面向上為 +Z。主銷轉向角正值代表左轉，側偏角正值表示行進方向偏向該輪左側。程式會依輪位將 Camber 轉成共用座標的 IA，IA 為正時向左的輪軸向上傾斜。若 TIR 的 `TYRESIDE` 為 Left，右輪送入模型的側偏角及 IA 會取反，算出的 `Fy` 及 `Mz` 再取反，轉回共同方向。結果表會顯示 Camber 和實際送入 TIR 的角度。CSV 的 `wheel_camber_deg` 代表 Camber，`camber_deg` 代表共用座標的 IA。

令 `k̂` 為沿 LBJ → UBJ 的主銷單位向量，`ẑ` 為路面向上的單位向量，`r` 為主銷接地點指向輪胎接地點的向量，`F` 為轉換至全車座標的接地力。機械拖距取 `r` 沿車輪朝向投影的相反數，輪胎接地點在主銷接地點後方時為正。

```text
回正合成力矩 = Mz − 機械拖距 × Fy
主銷合成力矩 = k̂ · (r × F) + Mz (k̂ · ẑ)
```

「前軸回正力矩（含 Fy）」沿路面向上軸加總左右輪的回正合成力矩。表格與 CSV 另列輪胎本身的 `Mz`（`mz_nm`）、Fy 經機械拖距的力矩（`trail_moment_nm`）與兩者合計（`aligning_total_nm`）。Pacejka 的 `Mz` 已包含輪胎的 pneumatic trail 效應。主銷合計是左右輪沿各自主銷的有號相加，對應兩側主銷角度有相同的增量。模型以穩態前進工況計算各輪。超出 TIR 標示的適用範圍會提示外插，輪荷為 0 時該輪各接地力與力矩均為 0。

前軸曲線將同一個偏移量 Δα 加到兩輪各自的側偏角，Δα = 0° 代表目前輸入的工況。單輪曲線直接以該輪側偏角為橫軸。前軸回正力矩圖會標出前軸合計的最大正值、最小負值及其角度，單輪圖則標註該輪的 `Mz` 峰值。前軸主銷力矩圖會在左輪、右輪及前軸合計三條曲線的峰值旁顯示力矩數字（N·m），圖下方表格也列出對應的 Δα。掃描端點會標註「邊界」或 `*`。用「姿態 CSV」匯出目前工況，「範圍 CSV」匯出曲線的全部數值。PNG 與 SVG 會保留圖上的峰值標記和數字。輪胎選擇與工況供目前工作台視窗使用。

計算核心與 TIR 讀取器取自 `new/Pacejka_tire_model`，預設輪胎檔取自 `new/Hoosier_43075_R20_W8_direct_candidate.tir`。副本位於 `suspension_geometry_lab/_pacejka/`，並附有原始授權。工作台可隨資料夾獨立啟動。

### 曲面、曲線與分布圖的目前位置

切換到 FV／SV 的各個曲面、RC／PC 位置分布，或 WE 的 caster 曲面、轉向曲線與 3D 軌跡時，會標出目前滑桿姿態的位置。曲面與位置分布使用白框粉紅點；多條輪端曲線各有與該曲線同色的點。深色標籤框顯示當前座標、數值與單位，3D 曲面另有垂直虛線輔助定位。

標記使用目前姿態的實際求解值，不吸附到最近網格，也不因滑桿移動重新縮放掃描範圍。移動滑桿時保留原有曲面網格、視角、縮放與平移；旋轉 3D 曲面時，點與標籤套用相同投影。前後軸、行程／pose 模式與圖表切換後，標記會使用對應的圖軸座標。PNG、SVG 與 HTML 報告均保留目前標記與數值標籤。

SV 曲面沿用實際 ride height：基準靜態的滑桿行程為前 0／後 0 mm，實際高度為前 50／後 50 mm，前 caster 約 5 deg；標籤同時顯示行程與實際高度。改到前上壓 15、後上壓 −10 mm 時，點移至前 ride height 35、後 60 mm，Z 使用當下 caster 等選定結果。切換 Heave／Pitch 後，點的 X／Y 改為當前 heave 與 pitch。

目前姿態無解、選定數值為 N/A，或超出該圖的掃描範圍時，不保留上一個有效點，也不將點夾到邊界，而是顯示原因。WE 設計 caster 超出 caster 曲面範圍時，該曲面的目前點不顯示，但固定設計 caster 的轉向曲線仍可正常標記。

靜態全車上方的「瞬心／Kingpin 連線與延長線」可一鍵隱藏或顯示瞬心參考線、瞬心與主銷接點組成的參考三角形，以及主銷延長線。切換會保留目前縮放與視角，PNG、SVG 與報告沿用目前顯示設定；硬點資料仍可完整匯出。

FV / SV 的「滑桿 / 曲面座標」選單同時決定掃描座標。FV 可用左右行程或 heave / roll；SV 可用前後 ride height 或 heave / pitch。SV 在前後行程模式下，滑桿控制輪側上壓，曲面橫軸換算成對應 ride height。

### 疊加 LapSimLab 懸吊工作範圍

在前 FV、後 FV 或 SV 頁按「匯入 LapSim CSV」，選取 LapSimLab 匯出的 `lap_result.csv`。切到 Camber、Camber gain、Anti、RC 或其他行程曲面，也可切到 RC／PC 位置分布圖。白色散點代表圈速模擬的各筆姿態。「顯示 LapSim 行程分布」可在三頁共用，匯入後會自動勾選。

匯入使用四輪的 `zs_minus_zu_*_mm`，轉號為上壓為正的簧下相對簧上位移。FV 使用該軸的左右輪位移，SV 使用前、後軸各自的左右輪平均。求解以輪心相對車身的位移定位姿態，再以該姿態的接地參考點換算現有圖軸，並依目前專案幾何重算各項數值。超出掃描行程或無有效幾何數值的資料會列入圖上的略過筆數。匯入資料在目前視窗使用。

### 圈速過彎 Camber 分布

匯入含有 `roll_deg`、`pitch_deg`、`heave_mm` 及轉彎方向的完整 CSV 後，可在前 FV／後 FV 的圖表選單選「LapSim 過彎 Camber 分布」。直方圖每格 0.25°，柱高為該角度區間的樣本數。藍色為內側，黃色為外側。空心柱套用初始 Camber 與車身姿態，實心柱另包含懸吊行程造成的輪軸轉角。游標移到圖上可查看該區間各組的樣本數。下方表格列出有效樣本數及最小至最大角度。

前 FV、後 FV 與 WE3D 轉向的 Camber 分布均預設疊加各組同色的**常態分布擬合曲線**。平均值 μ 與標準差 σ 由該組實際角度樣本計算（σ 採母體標準差，分母 N），曲線高度為 `N × 0.25° × 常態機率密度`，對齊直方圖的筆數尺度；不使用分組中心代替原始資料。空心柱的曲線使用虛線，實心柱使用實線。初始視圖包含各組 μ±4σ 的曲線範圍。游標提示亦列出 μ、σ；少於 2 筆樣本或 σ 近乎零時不繪製該組曲線，並在提示中說明。常態擬合提供形狀比較，不表示實際分布必然符合常態。

「顯示常態分布曲線」可獨立切換全部曲線；原本的類別勾選會同時控制該組柱狀與曲線。切換保留縮放／平移，PNG、SVG 與 HTML 報告採用目前顯示結果，CSV 保留實際樣本。

直方圖上方的「顯示類別」可分別勾選內側、外側各組。每頁會記住自己的勾選狀態。切換顯示時使用同一套分箱與圖軸範圍。

使用 `curvature_1_m` 判斷方向，缺少該欄才使用 `ay_g`。正值為左彎，左輪是內側，負值為右彎，右輪是內側。直線不列入分布。同一軸的四組柱使用相同的有效彎道樣本及角度區間，兩側行程皆須在掃描範圍內且有解。每格包含左界，例如 0° 計入 0°～0.25° 這一格。

程式以 FV 求得輪軸相對車身的轉角，再用 LapSim 的合成 Roll（左側抬起為正）與 Pitch（車頭抬起為正）旋轉到平坦路面座標。輪胎造成的車身側傾已在合成 Roll 內。Heave 為向下為正的平移，會改變輪心高度。Camber 以輪胎上端向外為正，靜態輪軸沿用 FV 的零外傾基準。FV 圖表使用前視幾何與車身姿態估算。此圖的「範圍 CSV」可匯出每筆樣本的車身姿態、輪心高度、內外側輪位及前後比較值。

在 WE3D 輪端匯入另外含有 `steer_FL_deg`、`steer_FR_deg` 的 CSV 後，同一圖表選項會顯示前輪內外側各三組。空心柱為純姿態，深色實心柱為姿態＋懸吊，亮色實心柱為姿態＋懸吊＋轉向，全部共用 0.25° 的角度區間和相同彎道樣本。

轉向組沿用前 FV 求得的懸吊姿態。主銷的橫向與垂直分量取當下上下球接點差值，縱向分量沿用 WE3D 的靜態三維主銷。各輪 CSV 轉角直接當作繞各自向上主銷的右手旋轉角，再以車身姿態換算對地 Camber。這是 FV 與 WE3D 的幾何疊合，轉向角使用 LapSim 的估算值。「範圍 CSV」另含左右前輪依內外輪位分組的轉角與轉向後 Camber。

### 上壓／下垂行程與角度範圍

掃描設定將行程分為「懸吊上壓行程」與「懸吊下垂行程」，兩格皆輸入非負的 mm 數值。例如上壓 40、下垂 10，表示各輪行程為 −10～+40 mm。兩格各允許 0～200 mm，可將其中一格設為 0，但不可同時為 0。前後 FV、SV 的行程滑桿與掃描範圍共用這組限制；網格保留上下界，跨越零位時也保留靜態 0 mm。

原本的 pitch／roll 範圍欄位用於 Heave／Pitch、Heave／Roll 模式的角度滑桿與掃描，現在已移除手動範圍輸入；兩種姿態操作模式與 pitch／roll 計算結果仍保留。

Heave／Roll 不再有獨立角度上限，直接由左右輪行程控制。Heave 是左右行程的平均；固定 Heave=h、行程上下限為 lo／hi 時，兩輪可用的反向行程為 `±min(h−lo, hi−h)`，再以實際接地點位置計算 Roll 滑桿範圍。改變 Heave 時，原有 Roll 若會使任一輪超行程，就收回新的可達邊界；Heave 到達 lo 或 hi 時，Roll 自然為 0。若連桿幾何先到達不可達位置，也會限制在該幾何分支內。

Heave／Roll 曲面直接掃描完整左右輪行程組合，再轉為實際 Heave、Roll 座標；不再使用固定的角度矩形裁切範圍，因此邊界通常呈菱形或曲邊。各點、目前位置標記與 CSV 均保留相同的左右行程與換算結果。Heave／Pitch 維持由反向行程組合推導參考 pitch 範圍，每個組合再檢查前後輪行程；超限或幾何不可達時標為無解。

參數模式下，前後軸各以「軸端 Anti 比例＋SVSA」定位靜態 SVIC，兩個輸入都以朝另一軸為水平正向。SVIC 相對接地點的高度為 `Anti 比例 × h/L × SVSA`。例如前軸輸入 `0.20` 和 `3 m`，基準車的前 SVIC 在接地點後方 3 m、上方約 118.3 mm。0% Anti 對應水平的 CP–SVIC 線。

共用設定與 SV／靜態頁可編輯每軸這兩個輸入。煞車與驅動力分配在結果中加權，調整分配時可留在同一姿態查看結果。硬點模式則用原始 XYZ 求得 SVIC，再反算軸端 Anti 和 SVSA。

開啟版本 1～5 專案時，程式按舊公式還原 CP–SVIC 線與實際有號 SVSA。版本 6 專案只需將前軸 Anti 輸入反號，即可保留原瞬心。硬點專案會保留原始 XYZ。若舊硬點專案的備用參數設計因兩條力線平行而無有限 SVIC，該軸的備用 SVSA 會採用舊檔中的有效值或基準值。儲存時寫成版本 7。

掃描預設每軸 21 點，FV / SV 共 441 個組合，解析度可設為 5–51 點。WE 除 caster × steering 網格外，另輸出目前設計 caster 的 steering 曲線。計算在背景執行；改變設定會取消過期結果。不可達姿態會保留錯誤原因，曲面會留空格，CSV 的 `valid` 與 `error` 可用來篩選。

## 單位、座標與計算定義

- JSON 長度一律 m、角度 deg、質量 kg、剛性 N/m；Anti 比例 `0.2` 表示 20%，允許負值或超過 100%。前煞車比例介於 0 與 1；前軸驅動力比例允許 0～1。UI 欄位標示各自單位。
- 靜態全車與 WE：X 向前、Y 向左、Z 向上。WE 顯示右輪 FR / RR，座標原點在前軸中心地面；後軸 X 約為負軸距。WE 正轉角為繞向上主銷的右手正向。
- FV 來源座標：橫向 X 向車右、垂直為 Y，車身座標 CSV 使用 x_m／z_m；動態圖轉為目前接地座標 x′／y′。正行程為輪側接地參考點相對車身向上。正 roll 為右接地點較高。
- FV camber 相對當下左右接地點連線；輪胎上端向外為正。`camber_gain_*_deg_per_mm` 是固定另一輪行程時，該輪 camber 對自身行程的局部偏導，包含地面基準改變；以 ±0.01 mm 中央差分求值。它不同於純 heave 曲線的總斜率。
- SV 來源 X 由前往後，前軸約為 -wheelbase、後軸為 0。正 pitch 為後接地點較高。`ride_height_*_mm = 靜態車底離地高 × 1000 − 對應輪側行程`；此處是 2D 姿態的等效高度，不包含完整車身姿態平衡。
- RC / PC 使用隨接地連線移動、旋轉的座標系：原點在當前兩接地點的中點。FV 的 x′ 由左輪指向右輪，SV 的 x′ 由前輪指向後輪；y′ 是 x′ 逆時針旋轉 90° 的向上法線。因此 y′ 就是到當前接地線的有號垂直高度，x′ 是沿線方向相對中點的位置。計算式為 `x′=(P−O)·u`、`y′=(P−O)·n`。
- 曲面、位置分布與主要數值使用 `rc_x_prime_mm` / `rc_y_prime_mm`、`pc_x_prime_mm` / `pc_y_prime_mm`；另以 `*_world_x_mm` / `*_world_z_mm` 保留固定車身座標作查核。舊版結果的 `rc_x_mm` / `rc_z_mm` 與 `pc_x_mm` / `pc_z_mm` 是固定座標，與新欄位的基準不同。
- FV／SV 動態機構統一畫在目前接地座標 x′／y′ 中。全部連桿、輪胎、CG、RC／PC、零位參考點與座標箭頭均套用同一個平移與旋轉，接地線在圖中為 y′=0；CG 與車身接點會反映升降、roll／pitch。幾何圖維持等比例，滑動時保留縮放與視角。
- FV 圓點標示：粉紅實心 RC、白色大空心 RC0、黃色 CG、青色 IC L、紫色 IC R；均附名稱。RC0 是當前專案零行程的原始 RC；CG 與 RC0 在原始車身座標中固定，在目前接地座標中的顯示位置則會隨車身姿態變動。零行程 RC 與 RC0 重疊時，仍可看見外圈與中心點。SV 同樣標示 PC / PC0、CG 與前後 IC。關閉力線不會隱藏座標軸或圓點。
- SVSA 是接地點至側視瞬心的有號水平距離，正值朝另一軸。參數模式用它設定幾何，硬點模式由 SVIC 反算。
- `clearance_steer_deg` 是靜態輪圈／避讓構造的設計轉角（原值 36 deg）；與 WE 掃描的 `analysis.steer_deg`（原值 ±30 deg）分開保存。

### 滑桿姿態、CG 與 Anti 的座標基準

滑桿改變輪側行程後，原始運動求解使用固定車身座標；目前前後接地點決定接地原點 O、沿接地線方向 u 與向上法線 n。動態圖使用 `P_contact = R(−pitch) · (P_body−O)`；FV 的 roll 亦採相同轉換。這是同一份幾何的座標轉換，不會修改硬點或把 CG 移出車身。

CG 是車身固定點，因此其車身座標保持設計值；在圖表使用的接地座標中，位置必須隨車身升降與俯仰更新。`cg_x_prime_mm`、`cg_y_prime_mm` 為當前位置，`cg_height_mm` 即 CG 至接地線的有號垂直距離。基準車前後輪同時上壓 15 mm 時，CG 離地高度由 301.645151 mm 降至 286.645151 mm。接地座標屬道路參考，不能將 CG 鎖定在其固定高度，否則會失去車身 heave／pitch 的效果。

2026-11-04 修正前，Anti 的斜率已使用當前接地座標，但軸距與重心高度仍採初始設定值。現在斜率、接地點間距與 CG 高度均由目前姿態計算：`L_current=|P_rear−P_front|`、`h_current=(CG_body−O)·n`，並用相同參考量計算所有姿態與掃描點。非正 CG 高度或無有限斜率時，Anti 顯示 N/A。[ARD 的動態 Anti 說明](https://docs.appliedracingdynamics.com/setup/kinematics/#anti-dive-anti-lift-and-anti-squat)亦將當前軸距、ride height 與 pitch 下的 CG 高度作為參考量。

車輛設定中的 CG 高度代表零行程設計值。各姿態的 Anti 依下述力分配計算加權值。

### 輪內馬達的接地點 Anti

模型假設輪內馬達定子與輪上碟煞卡鉗都固定於 upright，反作用扭矩經懸吊連桿傳遞。準靜態煞車與加速共用同一條接地點 CP→SVIC 力線。

令 b 為前軸煞車力占比，d 為前軸驅動力占比。`vehicle.drive_force_front` 的 0、1、0.5 分別表示後驅、前驅及前後各半。以前軸朝車尾、後軸朝車頭為水平正向，計算接地點至 SVIC 的有號斜率 `m = Δz/Δx`。結果表、曲面和匯出的軸端 Anti 為 `A = 100 × L/h × m`，其中 L 是當前接地點間距，h 是當前 CG 高度。

| 工況 | 前軸加權 Anti（%） | 後軸加權 Anti（%） |
|---|---|---|
| 煞車 | b × A_front | (1−b) × A_rear |
| 加速 | d × A_front | (1−d) × A_rear |

若要換算成以車頭為 X 正向的有號幾何比例 G，前軸取 `G = −A`，後軸取 `G = A`。無有限瞬心、力線近乎垂直或 CG 高度非正時，無法定義的比例顯示 N/A。CG 高度有效時，該軸未分配到力的工況結果為 0。

前後兩條 CP–SVIC 線平行時，俯仰中心 PC 顯示 N/A。各軸的 SVIC 和 Anti 仍可由各自的幾何求出。

基準專案前後軸的 Anti 輸入約為 +28.5714%／+33.3333%，SVSA 約為 3.474681／2.984219 m。在零行程，70%／30% 煞車分配得到 +20%／+10%，50%／50% 驅動分配得到 +14.2857%／+16.6667%。

## 模型適用範圍

FV 沿用雙圓求交的 2D 四連桿運動，車身上下接點固定，零位統一使用套件內靜態求解器與目前 JSON 專案。每次求解都以凍結零位為基準，防止多次滑動造成累積漂移；反算後會核對實際行程殘差。接點延長線平行時，RC / PC 顯示 N/A。

SV 沿用原 `sus_sv_v4.py` 的 **Au / Al 固定切線路徑**，維持羊角剛性，並以接地參考點高度反算行程。Caster 隨羊角姿態與接地線傾角重新計算。Anti 是以各軸水平正向表示的準靜態幾何比例。

SV 下方姿態表格同時列出前／後輪的 **Caster（deg）**與 **Mechanical trail（mm）**，隨前後行程或 Heave／Pitch 即時更新。Trail 使用當下主銷延長線與前後接地點連線的交點，沿路面量取至該輪接地點的有號距離；正負方向沿用該軸的 mechanical trail 設計定義，零行程時與設計值一致。主銷與路面平行、無唯一交點時顯示 N/A。此值沿用 SV 平面機構與接地參考，不包含輪胎 pneumatic trail；姿態／範圍 CSV 同步提供 `trail_front_mm`、`trail_rear_mm`，HTML 報告也包含這兩項。

WE 使用靜態全車解出的主銷軸與輪心做 Rodrigues 旋轉，不使用原 WE 腳本另外建立的主銷公式。固定主銷 caster 本身不隨 steering 改變；因此提供「不同設計 caster × steering → 輪軸傾角」曲面，以及固定設計 caster 的水平曲線。

WE 區分兩個點：`material_*` 是零轉角接地材料點隨輪胎剛體轉動的位置；`contact_*` 是旋轉後、以負載半徑建模的輪胎中心圓最低點。前者到固定主銷的垂距理應恆定，後者的選點改變才會產生半徑變化。圖中的輪胎外形保留自由半徑；未求解有限胎寬的胎肩接觸、彈性變形、轉向頂升平衡，也未將 FV / SV 行程與 steering 耦合成完整 3D 懸吊求解。

在前 FV、後 FV、SV 側視或靜態全車頁，按底部「STEP 匯出」存成 `.step`。檔案使用 AP214 格式，單位為 **mm**，適合匯入 CAD 作為建模參考。座標固定於車身，X 向前、Y 向左、Z 向上。前、後 FV 分別位於各軸 X 平面，SV 位於 Y=0。FV／SV 使用目前滑桿姿態；線框模式依「顯示 IC / 力線參考」決定是否納入參考線，實體模式僅輸出實際桿件與勾選的輪胎。

靜態全車輸出已套用設計的 3D 連桿中心線。參數模式採用計算出的 A 臂接點（包含手動指定的 X），硬點模式採用專案的 XYZ。四輪連桿可匯入同一份 CAD 檔案，旋轉視角或開關 FV／SV 顯示平面時，STEP 座標保持一致。

按「STEP 匯出」後會先出現匯出選項，可勾選「匯出實體」、「包含輪胎」與「輪胎套用已設定的靜態 Camber」，下一步再選儲存位置。「匯出實體」預設不勾選，其餘兩項預設勾選。未勾實體時，每輪以兩個真正的 STEP `CIRCLE` 表示圓柱兩端，半徑採輪胎自由半徑，兩圓圈間距採胎寬。靜態全車共 8 圓圈，前／後 FV 各 4 圓圈；SV 以當前前後輪心的 X／Z 位置，按輪距鏡射四輪，共 8 圓圈，機構線稿仍位於 Y=0。

勾選「匯出實體」後可輸入「懸吊管徑（mm）」，預設 **20 mm**，必須為大於 0 的有限數值。上下 A 臂腿與立柱以該直徑建立兩端封閉的實心圓柱桿件，輪胎則直接建立自由半徑、胎寬對應的封閉圓柱。每根桿件與每顆輪胎均為獨立 STEP 實體，保留原中心線與端點，沒有合併、接頭、管壁厚度或相交修剪。靜態全車為 20 根桿件與 4 顆輪胎；前／後 FV 為該平面內的上下臂及立柱共 6 根桿件與 2 顆輪胎；SV 為 Y=0 的 2 根立柱與鏡射的 4 顆輪胎。FV／SV 沿用平面運動模型；完整四輪 3D A 臂實體請從靜態全車頁匯出。實體使用解析圓柱面與平面端蓋組成封閉 B-rep，不需安裝 CAD 套件。

勾選靜態 Camber 時使用當前機構姿態加車輪安裝角；取消勾選只移除靜態安裝角，FV 行程造成的 Camber 與 SV 機構姿態仍保留。兩種選擇均不移動輪心或懸吊線稿。原本 FV 的平面輪胎矩形及 SV 的平面輪圈線會由這些圓圈取代；不包含輪胎時也不輸出原平面輪胎輪廓。選項會在本次開啟工具期間保留，上壓／下垂姿態與力線開關仍沿用目前頁面的設定。

CSV 使用 UTF-8 BOM，可直接以 Excel 開啟。`*_mm`、`*_deg`、`*_pct`、`*_m` 與 `*_deg_per_mm` 表示欄位單位；`axis_x` / `axis_y` 是所選掃描座標，SV 行程模式為換算後前 / 後 ride height。曲面圖會標示座標與單位。

FV / SV 硬點 CSV 的 `x_m` / `z_m` 是固定車身座標，`x_prime_m` / `y_prime_m` 是當前接地中點座標，與動態圖中的點位一致，包括 CG。姿態／範圍 CSV 另有 `cg_height_mm`、`cg_x_prime_mm`、`cg_y_prime_mm`，SV 包含 `wheelbase_mm`。報告的輸入快照另存接地座標原點與兩個單位基底；PNG / SVG 與報告使用同一份接地座標圖形。
